> 技术栈：Vue 3 + TypeScript + Vite + Electron + Naive UI + xgplayer（桌面端）+ Node.js + Express（后端）  
> 工程形态：**pnpm monorepo**  
> 片源 / 搜索：**对接 [LibreTV](https://libretv.liumingye.cn/) 同源协议与内置采集站**  
> 文档版本：v1.2  
> 更新日期：2026-11-06  
> 状态：Phase 0 脚手架已完成，可本地 `pnpm dev`

## 1. 项目概述

### 1.1 一句话定位

基于 Electron 的桌面端长视频应用：交互参考腾讯视频（首页、频道、详情、播放器、我的），**内容发现与播放地址来自 LibreTV 聚合的第三方 Apple CMS 采集站**；自建 Express 负责 BFF 代理聚合、用户体系、观看进度与收藏。

### 1.2 目标用户

- 需要桌面客户端体验（窗口、托盘、快捷键）的影音浏览用户
- 希望「搜索即播」且进度可跨会话记忆的个人用户

### 1.3 产品边界

| 不做项 | 说明 |
|--------|------|
| 管理后台 / 媒资自建入库 | 本期明确不做 |
| 自建本地片源库为主流程 | 搜索与片源走 LibreTV 协议；本地扫盘可作 P2 |
| VIP 支付、会员开通 | 仅可预留 UI，无支付 |
| 弹幕 / 评论商业方案 | 后续可选 |
| 直播 IPTV | 后续评估（LibreTV 新版有直播，本期站点以点播为主） |
| 复制腾讯视频官方素材/品牌 | 仅参考信息架构与交互，视觉自研 |

### 1.4 合规说明（必读）

LibreTV 官方声明：站点**仅提供搜索聚合**，不存储、不上传视频；结果来自第三方公开采集接口。本项目同样：

- 不爬取腾讯视频等正版站盗链
- 不托管视频文件
- 仅转发/聚合公开 CMS 接口返回的播放地址
- 使用者须遵守当地法律法规，不得用于侵权传播

## 2. 技术选型

### 2.1 总体架构

```
┌──────────────────────────────────────────────────────────┐
│  Electron 主进程                                           │
│  窗口 / 托盘 / 全局快捷键 / 本地存储 / 打包更新               │
└────────────────────────────┬─────────────────────────────┘
                             │ IPC
┌────────────────────────────▼─────────────────────────────┐
│  渲染进程：Vue 3 + TS + Vite + Vue Router + Pinia          │
│  UI：Naive UI + 自定义暗色布局（仿腾讯视频）                 │
│  播放：xgplayer + HLS                                      │
└────────────────────────────┬─────────────────────────────┘
                             │ HTTP（仅打自家 BFF）
┌────────────────────────────▼─────────────────────────────┐
│  apps/server · Express BFF                                 │
│  · 用户 JWT / 进度 / 收藏 / 历史（SQLite）                   │
│  · LibreTV 适配层：多源并行搜索、详情解析、m3u8 代理         │
└────────────────────────────┬─────────────────────────────┘
                             │ 出网
┌────────────────────────────▼─────────────────────────────┐
│  第三方 Apple CMS 采集站（与 LibreTV 内置源对齐）            │
│  可选回退：经 https://libretv.liumingye.cn/proxy/ 转发      │
└──────────────────────────────────────────────────────────┘
```

**为何经自家 BFF，而不是渲染进程直连 LibreTV？**

1. 该站 `/api/search`、`/api/detail` 本质是前端 `fetch` 猴子补丁，真实流量走 `/proxy/{encodeURIComponent(url)}`
2. 服务端聚合可并行多源、统一超时、过滤成人源、隐藏上游地址细节
3. Electron 播放 m3u8 常遇 CORS / 防盗链，需要服务端代理改写分片地址
4. 用户进度、收藏仍需自建持久化

## 3. LibreTV 片源对接说明

### 3.1 目标站点实勘结论

目标站 https://libretv.liumingye.cn/ 为 **LibreTV 经典版（静态前端 + `/proxy/`）**，不是 Next.js 新版。

| 能力 | 站点行为 | 本项目对接方式 |
|------|----------|----------------|
| 内置源列表 | `js/config.js` → `API_SITES` | 同步到 `apps/server` 的 `libretv-sources.ts`（可配置覆盖） |
| 搜索 | 虚拟 `/api/search` → 实际 `/proxy/` + CMS `?ac=videolist&wd=` | BFF：`GET/POST /api/vod/search` |
| 详情 / 分集 | 虚拟 `/api/detail` → CMS `?ac=videolist&ids=` | BFF：`GET /api/vod/detail` |
| 播放 | 解析 `vod_play_url` 得到 m3u8 列表 | BFF 返回剧集 URL；播放走 `/api/proxy` |
| 代理 | `GET /proxy/{encodeURIComponent(upstream)}` | BFF 自实现等价代理（优先）；失败可回退该站 |

已验证：经该站 `/proxy/` 请求暴风资源等 CMS 搜索可返回标准 JSON（`code/list/vod_name/...`）。

### 3.2 Apple CMS 协议（核心）

```
搜索：{apiBase}?ac=videolist&wd={关键词}&pg={页码}
详情：{apiBase}?ac=videolist&ids={vod_id}
```

列表项关键字段（归一化后供前端使用）：

| CMS 字段 | 含义 |
|----------|------|
| `vod_id` | 源站内 ID |
| `vod_name` | 标题 |
| `vod_pic` | 封面 |
| `vod_remarks` / `vod_score` | 更新状态 / 评分 |
| `type_name` / `vod_class` | 类型 |
| `vod_actor` / `vod_director` | 演员 / 导演 |
| `vod_content` | 简介 |
| `vod_play_url` | 播放地址串 |

`vod_play_url` 解析规则（与 LibreTV 一致）：

1. 多线路用 `$$$` 分隔  
2. 单线路内多集用 `#` 分隔  
3. 每集形如：`第01集$https://xxx/index.m3u8`

### 3.3 内置源（与目标站对齐，摘录）

实现时以站点 `config.js` 为准做完整同步；示例如下：

| sourceKey | 名称 | API |
|-----------|------|-----|
| dyttzy | 电影天堂资源 | `http://caiji.dyttzyapi.com/api.php/provide/vod` |
| ruyi | 如意资源 | `https://cj.rycjapi.com/api.php/provide/vod` |
| bfzy | 暴风资源 | `https://bfzyapi.com/api.php/provide/vod` |
| tyyszy | 天涯资源 | `https://tyyszy.com/api.php/provide/vod` |
| ffzy | 非凡影视 | `http://ffzy5.tv/api.php/provide/vod` |
| heimuer | 黑木耳 | `https://json.heimuer.xyz/api.php/provide/vod` |
| zy360 | 360资源 | `https://360zy.com/api.php/provide/vod` |
| … | … | 其余见站点配置 |

部分源带 `detail` 字段：列表接口可能不含完整播放地址，需降级抓取详情页 HTML 抽 m3u8（二期可做；一期优先走 `ac=videolist&ids=` 能返回 `vod_play_url` 的源）。

### 3.4 推荐的 BFF 调用链

**搜索（并行聚合）**

```
客户端 POST /api/vod/search { wd, sources?: string[], filterAdult?: true }
  → server 对每个 source 请求 CMS（或 via LibreTV proxy）
  → 归一化 + 去重(sourceKey+vodId) + 成人过滤
  → { list, failures[] }
```

**详情**

```
客户端 GET /api/vod/detail?source=bfzy&id=123
  → CMS ids 查询
  → 解析 episodes[] / lines[]
  → { meta, lines: [{ name, episodes: [{ name, url }] }] }
```

**播放**

```
xgplayer 加载 url
  直连失败 → 改用 GET /api/proxy?url=  （服务端改写 m3u8 分片为继续走代理）
```

### 3.5 首页内容策略（无自建片库时）

因不做管理后台、不维护本地片库：

| 模块 | 一期方案 |
|------|----------|
| 首页主内容 | **搜索驱动** + 「继续观看」（本地进度） |
| Banner / 热门 | 用豆瓣热门标签接口（LibreTV `douban.js` 同源思路）或固定热搜词批量搜聚合（P0 可用热搜词） |
| 频道页 | 以类型关键词 / CMS `t` 分类（若源支持）或预设关键词搜索结果充当频道 |

> 频道「电影/剧集/综艺…」在无运营片库时，本质是**带分类意图的搜索/推荐块**，UI 仍做成腾讯视频式频道导航。

## 6. 数据模型（自建部分）

片库不落库；只存用户侧数据：

```
User            id, username, passwordHash, nickname, avatar, createdAt
Favorite        id, userId, sourceKey, vodId, title, cover, createdAt
WatchProgress   id, userId, sourceKey, vodId, episodeIndex, positionSec,
                durationSec, title, cover, updatedAt
# 观看历史可由 WatchProgress 按 updatedAt 排序得到
```

媒资详情运行时从 CMS 拉取，可用内存短缓存（如 5～10 分钟）。

## 7. 自建 BFF · REST 草案

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/auth/register` | 注册 |

## 11. 风险与对策

| 风险 | 对策 |
|------|------|
| 采集站不稳定 / 挂掉 | 多源并行；failures 展示；源健康度（P1） |
| LibreTV 站点改版或限流 | **优先 `direct` 直连 CMS**；`via_libretv` 仅作回退 |
| m3u8 CORS / 防盗链 | 强制可切换的 `/api/proxy`；xgplayer 错误回调自动改代理 URL |
| 部分源无 `vod_play_url` | 标记不可播；P1 做 detail 页 HTML 降级解析 |
| 法律与内容风险 | 产品内展示免责声明；默认过滤成人源；不提供批量下载工具（下载功能延后） |
| 清晰度切换不适用 | UI 改为线路/换源，避免假清晰度 |
